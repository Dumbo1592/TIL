Hash(해시):
해싱은 임의의 크기를 가진 데이터를 정해진 크기 또는 범위의 값(해시값)으로 변환하는 것을 말한다.
해시 테이블에서는 key로부터 해시값을 구하고, 이를 배열의 인덱스로 변환하여 데이터를 저장하거나 찾는다.
해시값이 곧바로 배열의 인덱스가 되는 경우도 있지만, 해시값에 나머지 연산 등을 적용해 인덱스를 구하기도 한다.
같은 key에 대해서는 같은 결과가 나와야 하지만, 서로 다른 key가 같은 결과를 갖는 것은 가능하다.
충돌이 적고 테이블의 크기가 적절하게 관리되면 탐색, 삽입, 삭제는 평균적으로 O(1)에 처리할 수 있다.
다만 충돌이 심해지면 최악의 경우 O(n)이 걸릴 수 있다. 여기서 n은 저장된 항목 수이다.
이 시간 복잡도는 key의 해시 계산과 비교 비용을 O(1)로 보는 일반적인 설명이다.

1. Direct Addressing Table:
Direct Addressing Table(직접 주소 테이블)은 key-value 쌍의 데이터를 저장할 때 key를 배열의 인덱스로 직접 사용하는 방식이다.
예를 들어 key가 400이면 배열의 인덱스 400에 해당 value 또는 데이터를 가리키는 참조를 저장한다.
해당 위치에 반드시 key와 포인터를 함께 저장해야 하는 것은 아니다. 인덱스 자체로 key를 알 수 있다.
빈 위치를 NULL 등으로 표시한다면, 삽입 시 해당 위치에 데이터를 넣고 삭제 시 다시 빈 상태로 표시하면 된다.
탐색 시에는 해당 key를 인덱스로 사용해 바로 접근한다.
테이블이 이미 할당되어 있다면 탐색, 삭제, 삽입, 갱신은 모두 O(1)이다.
단, 가능한 key가 정수 0~M이라면 M+1개의 칸이 필요하다.
따라서 가능한 key의 범위가 넓고 실제 저장할 데이터가 적으면 공간 낭비가 크다.

2. Hash Table:
Hash Table은 key를 해시 함수로 계산하여 얻은 인덱스에 key-value 항목을 저장하는 방식이다.
여기서는 해시 계산과 인덱스 변환을 합쳐 h(k)라고 표현한다.
테이블의 칸 수가 m이면 h(k)는 0~m-1 범위의 인덱스를 반환한다.
예를 들어 정수 key에 h(k) = k % m을 사용할 수 있다.
key는 정수뿐 아니라 문자열 등도 가능하며, 자료형에 맞는 해시 계산 방법이 필요하다.
해시 테이블은 h(k)만큼의 공간을 사용하는 것이 아니다. h(k)는 저장 위치를 나타내는 인덱스다.
배열 자체에는 m개의 칸을 할당하며, 체이닝에서는 항목을 저장할 노드 등의 공간도 추가로 필요하다.
따라서 체이닝 방식의 전체 공간 복잡도는 O(m+n)이다.
직접 주소 테이블과 달리 가능한 key 전체 범위만큼 배열을 만들 필요가 없어 공간 낭비를 줄일 수 있다.

2-1. Collision(충돌):
충돌은 서로 다른 key가 같은 테이블 인덱스로 매핑되는 경우를 말한다.
즉, k1 != k2인데 h(k1) = h(k2)인 경우다. 실제로 데이터를 덮어써야만 충돌이 발생하는 것은 아니다.
예를 들어 h(k) = k % 10이면 key 1과 11은 모두 인덱스 1로 매핑된다.
가능한 key의 수가 테이블의 칸 수보다 많으면 모든 key에 대해 충돌을 없애는 것은 불가능하다.
좋은 해시 함수와 적절한 테이블 크기로 충돌을 줄이고, 체이닝이나 개방 주소법으로 발생한 충돌을 처리한다.
또한 인덱스가 같아도 key가 다를 수 있으므로, 탐색 시에는 저장된 실제 key를 비교해야 한다.

2-1-1. Chaining(체이닝):
체이닝은 충돌 자체를 줄이는 방법이 아니라, 같은 인덱스로 매핑된 여러 항목을 함께 보관하여 충돌을 처리하는 방법이다.
각 인덱스의 저장 공간을 버킷이라고 하며, 버킷마다 연결 리스트를 두는 방식이 대표적이다.
이 경우 각 노드에는 key-value 항목과 다음 노드에 대한 포인터 또는 참조를 저장한다.
테이블의 각 칸에는 해당 연결 리스트의 첫 노드에 대한 참조를 저장할 수 있다.
새 노드는 리스트의 앞이나 뒤에 연결할 수 있으며, 반드시 뒤에 추가해야 하는 것은 아니다.

예: h(k) = k % 10일 때
table[1] -> [key=1, value=A | next] -> [key=11, value=B | next] -> NULL

탐색할 때는 h(k)로 버킷을 찾은 뒤, 연결된 노드의 실제 key를 비교하여 원하는 항목을 찾는다.
삭제나 기존 key의 값 갱신도 먼저 해당 노드를 찾는 과정이 필요하다.
새 노드를 맨 앞에 연결하는 작업 자체는 O(1)이지만, 중복 key 확인이 필요하면 먼저 탐색해야 한다.
평균 버킷 길이는 n/m이며, key가 고르게 분산되면 탐색은 평균 O(1+n/m)이다.
n/m을 일정 수준으로 유지하면 평균 O(1)이지만, 모든 항목이 한 버킷에 몰리면 탐색은 O(n)이 된다.
체이닝의 버킷은 연결 리스트 외의 자료구조로도 구현할 수 있다.

참고: 파이썬 list와 연결 리스트의 차이
일반적으로 사용하는 CPython의 list는 객체 참조를 배열에 저장하는 동적 배열이며, 연결 리스트가 아니다.
리스트 이름은 리스트 객체를 참조하고, 리스트 객체가 원소 참조를 담는 배열을 관리한다.
각 원소가 다음 원소에 대한 참조를 갖는 구조가 아니므로, 이름이 객체를 참조한다는 이유로 연결 리스트가 되는 것은 아니다.
list의 인덱스 접근은 O(1), 맨 앞 삽입/삭제는 O(n), 맨 뒤 append는 분할 상환 O(1)이다.
분할 상환 O(1)은 여러 번의 append에 드는 총비용을 연산 수로 나누면 O(1)이라는 뜻이다.
개별 append는 내부 배열의 크기를 늘리는 경우 O(n)이 걸릴 수 있다.
파이썬에서 연결 리스트를 직접 구현하려면 노드와 노드 사이의 참조를 별도로 구성해야 한다.

3. Load Factor(적재율):
적재율은 테이블의 칸 수에 비해 얼마나 많은 항목이 저장되어 있는지 나타내는 값이다.
alpha = n / m (n: 저장된 항목 수, m: 테이블의 칸 수)
예를 들어 10개의 칸에 항목 7개가 있으면 alpha = 0.7이다.
체이닝에서는 한 버킷에 여러 항목을 넣으므로 alpha가 1보다 커질 수 있다.
이때 alpha는 전체 버킷에 대한 평균 항목 수이며, 모든 버킷의 길이가 같다는 뜻은 아니다.
개방 주소법에서는 칸 하나에 항목 하나만 저장하므로 alpha <= 1이다.
빈 칸을 이용해 원활하게 삽입하려면 alpha < 1로 관리해야 한다.
적재율이 높아지면 일반적으로 충돌 처리와 탐색에 드는 비용이 증가한다.
일정 기준을 넘으면 더 큰 배열을 만들고, 새 크기에 맞게 각 항목의 위치를 다시 계산하여 옮긴다(재해싱).
배열만 늘리고 기존 위치를 그대로 두면 새 탐색 경로와 맞지 않을 수 있다.
확장 기준은 구현에 따라 다르며, 특정 수치가 모든 방식에 공통으로 적용되는 것은 아니다.

4. Simple Uniform Hashing(단순 균등 해싱):
각 key가 다른 key의 배치와 독립적으로, m개의 버킷 중 어느 곳에나 1/m의 확률로 매핑된다고 가정하는 것이다.
특정 해시 함수나 충돌 해결 알고리즘의 이름이 아니라, 평균 성능을 분석하기 위한 이상적인 가정이다.
실제 함수는 같은 key에 같은 결과를 내지만, 입력 key들이 고르게 분산된다고 보고 분석한다.
이 가정에서도 충돌은 발생한다. 균등하다는 말이 모든 key의 인덱스가 서로 다르다는 뜻은 아니다.
체이닝에서 평균 탐색 비용 O(1+alpha)를 설명할 때 사용한다.
참고로 개방 주소법의 균등 해싱 가정은 각 key의 탐사 순서가 m개 칸의 모든 순열 중 균등하게 선택된다는 더 강한 가정이다.
최초 인덱스가 균등하다는 것만으로 전체 탐사 순서까지 균등해지는 것은 아니다.

5. Division Method(나눗셈법):
정수 key를 테이블 크기로 나눈 나머지를 인덱스로 사용하는 방법이다.
h(k) = k % m
예: m=11일 때 h(25)=3, h(36)=3이므로 충돌한다.
key들에 규칙이 있으면 나머지가 한쪽에 몰릴 수 있다.
예를 들어 m=10일 때 10의 배수인 key는 모두 인덱스 0으로 매핑된다.
단순한 나눗셈법에서는 2의 거듭제곱에서 멀리 떨어진 소수를 m으로 선택하는 것이 흔한 방법이다.
소수를 선택해도 충돌이 없어지거나 모든 입력에서 균등한 분포가 보장되는 것은 아니다.
문자열 등에는 먼저 정수 해시값을 구한 다음 나머지 연산을 적용할 수 있다.

6. Open Addressing(개방 주소법):
체이닝처럼 별도의 연결 리스트를 두는 대신, 모든 항목을 테이블 배열 안에 저장하는 충돌 해결 방식이다.
충돌하면 정해진 규칙에 따라 다른 칸을 차례로 확인하며, 이를 탐사(probing)라고 한다.
삽입, 탐색, 삭제에는 같은 key에 대해 동일한 탐사 순서를 사용해야 한다.
아래 공식에서 i=0, 1, 2, ...는 탐사 번호이며, i=0은 최초 위치다.
탐사는 무한 반복하지 않도록 횟수를 제한하고, 넣을 위치를 찾지 못하면 확장 및 재해싱 등을 수행해야 한다.

탐색과 삭제 시 주의점:
- 탐색 중 key를 찾으면 성공, 한 번도 사용되지 않은 빈 칸을 만나면 실패로 판단할 수 있다.
- 삭제한 칸을 단순히 빈 칸으로 바꾸면 뒤쪽으로 밀려 저장된 항목을 찾지 못할 수 있다.
- 따라서 흔히 EMPTY(미사용), OCCUPIED(사용 중), DELETED(삭제됨)를 구분한다.
- 탐색은 DELETED를 만나도 계속하며, 삽입은 해당 칸을 재사용할 수 있다.
- 삽입 시 삭제된 칸을 발견해도 탐색을 계속하여 같은 key가 뒤에 있는지 확인한 뒤 갱신하거나 삽입해야 한다.
- 삭제 표시가 많이 쌓이면 실제 항목 수가 적어도 탐색이 느려지므로 재해싱으로 정리할 수 있다.

6-1. Linear Probing(선형 탐사):
h(k, i) = (h_base(k) + i) % m
충돌하면 바로 다음 칸을 확인하며, 배열 끝을 넘으면 처음으로 돌아간다.
예: m=11, 최초 위치가 3이면 3 -> 4 -> 5 -> 6 -> ... 순서다.
구현이 간단하고 인접한 메모리를 읽어 캐시 활용에 유리하다.
하지만 사용 중인 칸들이 긴 덩어리로 뭉치는 1차 군집화(primary clustering)가 발생한다.
최초 위치가 달라도 같은 덩어리를 만나면 뒤쪽으로 계속 밀려날 수 있다.

6-2. Quadratic Probing(이차 탐사):
h(k, i) = (h_base(k) + c1*i + c2*i*i) % m
c1, c2는 선택한 상수다. 간단한 예로 (h_base(k) + i*i) % m을 사용할 수 있다.
예: m=11, 최초 위치가 3이고 i*i를 쓰면 3 -> 4 -> 7 -> 1 -> 8 -> ... 순서다.
연속된 칸만 확인하지 않으므로 선형 탐사의 1차 군집화를 완화한다.
하지만 최초 위치가 같은 key들은 동일한 탐사 순서를 따라가는 2차 군집화(secondary clustering)가 발생한다.
테이블 크기와 상수 선택에 따라 일부 칸만 반복 방문할 수 있어, 빈 칸이 있어도 삽입에 실패할 수 있다.
특히 m이 홀수 소수이고 i*i를 사용하는 방식은 테이블이 절반 미만으로 차 있을 때 빈 칸을 찾을 수 있다.
이 조건을 다른 이차 탐사 공식에 그대로 적용하면 안 된다.

6-3. Double Hashing(이중 해싱):
h(k, i) = (h1(k) + i*h2(k)) % m
첫 번째 함수 h1은 시작 위치, 두 번째 함수 h2는 이동 간격을 결정한다.
최초 위치가 같아도 이동 간격이 다르면 서로 다른 순서로 탐사하여 군집화를 줄인다.
h2(k)는 0이 아니어야 하고, 모든 칸을 방문하려면 h2(k)와 m이 서로소여야 한다.
예를 들어 m을 소수로 잡고 h2(k)를 1~m-1 범위로 정하면 이 조건을 만족한다.
정수 key에 대한 예: m=11, h1(k)=k%11, h2(k)=1+(k%10)
k=25이면 시작 위치는 3, 이동 간격은 6이므로 3 -> 9 -> 4 -> 10 -> 5 -> ... 순서로 탐사한다.
서로 다른 key라도 h1과 h2가 모두 같을 수 있으므로 충돌이 완전히 사라지는 것은 아니다.

7. 알고리즘 문제에서 활용하기:
직접 구현을 요구하는 문제가 아니라면 파이썬의 dict와 set을 사용하면 된다.
dict는 key-value 저장, set은 중복 제거와 존재 여부 확인에 사용한다.
위 탐사 공식들은 학습용 설명이며, 파이썬 dict가 이 공식 중 하나를 그대로 사용한다는 뜻은 아니다.
dict와 set의 key/원소는 해시 가능해야 한다. int, str, 해시 가능한 원소만 가진 tuple 등을 사용할 수 있다.
list, dict, set 자체는 해시 불가능하므로 key로 사용할 수 없다.

자주 쓰는 패턴:
- 빈도 계산: counts[x] = counts.get(x, 0) + 1
- 존재 여부: x in counts 또는 x in seen
- 기본값을 포함한 조회: counts.get(x, 0)
- 갱신/저장: table[key] = value
- 삭제: del table[key] (없는 key이면 KeyError)
- 두 수의 합: 현재 값 x를 볼 때 target-x가 이전 값들의 집합에 있는지 확인

실행 가능한 빈도 조회 예제: Python/hash_frequency.py
정수 목록을 한 번 세어 두고, 각 질의 값이 몇 번 나왔는지 조회한다.
값의 범위가 넓거나 음수여도 배열 인덱스 범위를 직접 확보할 필요가 없다.
원소 수 N, 질의 수 Q에 대해 평균 시간 O(N+Q), 빈도표 공간 O(U)이다(U: 서로 다른 값의 수).
예제 코드는 반환 결과 목록에도 O(Q) 공간을 사용한다.
